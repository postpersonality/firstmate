# Дело

Локальная панель задач Firstmate в браузере. Каждая карточка и строка берутся из бэклога Firstmate; собственной БД задач у «Дела» нет.
Прогресс и отчёты ревью читаются из выбранного дома Firstmate. Агентов запускает и ведёт Firstmate, «Дело» только показывает задачи и передаёт ему действия.

## Запуск

Требуется Node.js 24.10 или новее и установленный Firstmate с `tasks-axi`. Команды ниже содержат только имена команд и обычные аргументы; их понимают Bash и nushell. Запускайте из каталога `delo`.

```text
npm ci
npm start
```

Панель: `http://localhost:4317`.

Дом Firstmate выбирается так:

1. `--firstmate-home /путь/к/firstmate`;
2. переменная `DELO_FIRSTMATE_HOME`;
3. по умолчанию `../../firstmate` от папки проекта: для `~/Projects/<папка>/delo` это `~/Projects/firstmate`.

```text
bin/delo --firstmate-home /путь/к/firstmate list
```

`--home` и `DELO_HOME` устарели: они принимаются ради старых файлов сервиса и игнорируются. По этому пути ничего не читается, не создаётся и не записывается.

## Панель

Главный экран показывает ориентиры Firstmate: «Дела», «В фокусе» (до трёх закреплённых задач), «Ждёт меня», «В работе», «Дальше» и «Сделано», с группировкой по проекту и фильтром по виду задачи или «Личное». Закрепление меняет приоритет строки бэклога. Обзор обновляется каждые 30 секунд, пока вкладка видна.

«Новая задача» добавляет строку в бэклог: название, дело, вид (`ship` или `scout`), проект, описание, зависимость от другой задачи, дата «Отложить до» и отметка «Личное».
Выбранное дело записывается первой строкой описания: `Дело: <id>`.
URL из названия переносятся в начало описания строками `Источник: …`, без дублей.
Задача не запускается при создании.

Карточка задачи показывает название, «Зачем» из брифа, ссылки строки Firstmate (PR, рапорты, документы) и бриф: зачем, критерий готовности, контекст и ограничения. «Править» меняет название, описание и отметку «Личное»; прежнее описание уходит в архив заметок Firstmate. Бриф закрытой задачи заморожен.

Кнопки действий доступны в карточке, строках обзора, фокусе и списке задач дела и зависят от состояния строки:

- в очереди: «Взять в работу», «Пауза», «Закрыть», «Отказ»;
- на паузе: «Снять паузу», «Закрыть», «Отказ»;
- вопрос капитану или задача, ожидающая решения: «Ответить» или «Разрешить работу», «Позже», «Закрыть как неактуальную»;
- в работе: «Запросить остановку» и «Запросить закрытие», а если задача ждёт ответа, ещё «Ответить»: ответ снимает ожидание, и задача остаётся в работе;
- закрытая: «Вернуть».

«Взять в работу» и закрытие задачи в работе отправляют заметку firstmate: запуском и остановкой агентов управляет он. Карточка показывает такие запросы и их состояние; повторный щелчок по неподтверждённому запросу повторяет тот же запрос. Если Firstmate сейчас не принимает заметки, панель сообщает об этом.

«Закрыть как неактуальную» сначала просит подтверждение, затем сохраняет этот выбор в истории решения Firstmate и закрывает задачу.
Открытие страницы и отмена подтверждения ничего не меняют.
Строки показывают текущее состояние задачи; кнопки выполняют действие без перехода в карточку.
Пока запрос выполняется, все кнопки этой задачи в обзоре и фокусе недоступны; после ошибки можно повторить действие.

CLI доступен через `npm run delo --` или `bin/delo`:

```text
bin/delo list
bin/delo show идентификатор
bin/delo state идентификатор active|paused|done|dropped
bin/delo doctor
```

Новую задачу из терминала заводит `fm-tasks-axi.sh add`.

## Дела

Дело - строка бэклога вида `program`: она стоит в работе без исполнителя, и Firstmate никогда не передаёт её агенту.
«Новое дело» заводит такую строку с брифом (зачем, критерий готовности, контекст, ограничения) и строками `Источник: …`.
Раздел «Дела» на главном экране перечисляет открытые дела со счётчиками задач: в работе, ждёт меня, дальше, сделано.
Страница дела показывает бриф, задачи дела из бэклога по состояниям, «Закрыты раньше» из архива Firstmate и «Ссылки»: источники, ссылки дела и всех его задач без повторов.
Бриф можно править, пока дело открыто.
«Новый агент» в открытом деле заводит задачу дела и сразу отправляет firstmate заметку «возьми в работу».
Форма задаёт направление (оно становится описанием, а его первое предложение - названием), вид, проект для `ship`, исполнителя, отметку «Работаю в окне сам» и папку.
Описание задачи начинается строками `Дело: <id>`, `Исполнитель: <имя>` (если исполнитель выбран), `Интерактивно` (если отмечено) и `Папка: <путь>`.
Инструкции такой задачи, которые готовит `bin/fm-brief.sh`, включают бриф дела в момент подготовки; правка брифа доходит только до задач, инструкции которых ещё не готовы.
Страница задачи показывает выбранного исполнителя и того, кто на самом деле её выполняет.
«Закрыть дело» сразу закрывает дело без незакрытых задач.
Если незакрытые задачи есть, сначала появляется предупреждение с их списком; только после подтверждения firstmate получает по заметке «закрой задачу» на каждую, и дело закрывается.
«Вернуть» открывает закрытое дело снова, пока оно в бэклоге.
«Закрытые дела» показывают дела из архива только для чтения; «Продолжить» заводит новое открытое дело с тем же названием, брифом и источниками.

## Ревью

В «Новом деле» доступны «Ревью системной аналитики» и «Код-ревью».
Для СА обязательны HTTP(S) ссылка на документ и существующая папка контекстного репозитория; можно выбрать зарегистрированный проект или ввести абсолютный путь.
Для код-ревью нужна одна ссылка на задачу Jira или конкретный PR, контекстный проект можно указать дополнительно.
Создание дела добавляет дочернюю задачу; «Взять в работу» передаёт её Firstmate через обычный запрос запуска.
Агент собирает связанные эпики и задачи СА, дополняет локальное описание ссылками и исполняет ревью.
SA runner запускает существующий npm script, а код-ревью использует code-review-workflow.
Карточка и отчёт показывают наблюдаемые переходы, времена и итог; неполные этапы и неизвестный формат отмечаются явно.
Ошибка или отмена остаются ошибкой, даже если процесс сообщил код выхода 0.
HTTP сервер не запускает ревью, а запросы создания и запуска защищены от повторов.

## Пользовательский сервис systemd

Остановите прежний `npm start` через `Ctrl+C`, чтобы освободить порт 4317. Затем в обычном терминале, без `sudo`, выполните:

```text
npm run service:init
```

Команда создаёт `~/.config/systemd/user/delo.service` (или каталог из `XDG_CONFIG_HOME`), обновляет конфигурацию systemd, включает автозапуск при входе и запускает приложение. Повторная инициализация обновляет настройки и перезапускает сервис. Используются абсолютный путь к текущему Node.js, папка этого проекта и привычный PATH. Сервис запускается как `cli.ts serve` без `--home`; в файл всегда записывается `Environment=DELO_FIRSTMATE_HOME=…`: значение переменной, если она задана при инициализации, иначе тот же дом по умолчанию, что у сервера. После смены установки Node.js, переноса проекта или дома Firstmate повторите инициализацию.

Уже установленный сервис со строкой `--home /путь/.data` продолжает запускаться: флаг принимается и игнорируется, каталог не читается и не меняется.

После обновления кода:

```text
npm run service:restart
```

Перезапуск выполняет только `systemctl --user restart delo.service`. Переменные графического сеанса для фокусировки окна передаёт `service:init`; она же показывает состояние сервиса после запуска. После смены графического сеанса актуальные переменные должна передавать в systemd сама графическая сессия. Отдельный `npm start` одновременно с сервисом не запускайте.

Состояние, журнал и отключение автозапуска:

```text
systemctl --user status delo.service
journalctl --user -u delo.service -f
systemctl --user disable --now delo.service
```

Для разрешения только перезапуска из Codex оставьте глобальную политику без изменений. Создайте в этом проекте пустой `.codex/config.toml`, если его ещё нет, и файл `.codex/rules/delo-restart.rules`:

```python
prefix_rule(
    pattern = ["npm", "run", "service:restart"],
    decision = "allow",
)
```

После добавления правила перезапустите Codex с `codex resume --last`. Правило проекта разрешает указанную команду вне песочницы без подтверждения; инициализация в него не входит. Сопоставление можно проверить: `codex execpolicy check --rules .codex/rules/delo-restart.rules -- npm run service:restart`. Подробности — в [документации Codex о правилах](https://learn.chatgpt.com/docs/agent-configuration/rules). Правило нужно установить самостоятельно; скрипты сервиса его не добавляют.

## Проверка

```text
npm test
npm run check
npm run build
```

Тесты используют временные дома Firstmate, а команды агентов, Herdr и `systemctl` в них заменены заглушками. Каждый временный дом Firstmate получает ссылку `bin` на код Firstmate: по умолчанию `~/Projects/firstmate/bin`, другой путь задаёт `DELO_TEST_FIRSTMATE_BIN`. Тест сервиса проверяет только текст файла сервиса и не вызывает `systemctl`.
