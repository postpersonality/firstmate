# Дело

Локальная панель задач Firstmate в браузере. Каждая карточка и строка берутся из бэклога Firstmate; собственной БД задач у «Дела» нет.
Прогресс и отчёты ревью читаются из выбранного дома Firstmate. Агентов запускает и ведёт Firstmate, «Дело» только показывает задачи и передаёт ему действия.

## Запуск

Требуется Node.js 24.10 или новее и установленный Firstmate с `tasks-axi`. Команды ниже содержат только имена команд и обычные аргументы; их понимают Bash и nushell. Запускайте из каталога `delo`.

```text
npm ci
npm start
```

Панель: `http://localhost:4317`.

Дом Firstmate выбирается так:

1. `--firstmate-home /путь/к/firstmate`;
2. переменная `DELO_FIRSTMATE_HOME`;
3. по умолчанию `../../firstmate` от папки проекта: для `~/Projects/<папка>/delo` это `~/Projects/firstmate`.

```text
bin/delo --firstmate-home /путь/к/firstmate list
```

`--home` и `DELO_HOME` устарели: они принимаются ради старых файлов сервиса и игнорируются. По этому пути ничего не читается, не создаётся и не записывается.

## Панель

Главный экран показывает ориентиры Firstmate: «Дела», «В фокусе» (до трёх закреплённых задач), «Ждёт», «В работе», «Дальше» и «Сделано», с группировкой по проекту и фильтром по виду задачи или «Личное».
Закрепление меняет приоритет строки бэклога.
Обзор обновляется каждые 30 секунд, пока вкладка видна.

В «Ждёт» попадают подтверждённые ожидания ответа, действий Firstmate, ревью, слияния, посадки, зависимости или отложенного условия, а также явные паузы и ограничения квоты.
Строка показывает причину и ответственного, когда он известен.
Припаркованная задача остаётся в «Ждёт» с пометкой «Припаркована», причиной и кнопкой «Снять паузу», без требования чьего-либо ответа.
Закрытая задача остаётся в «Сделано» даже при сохранённом исполнителе.
Задача, взятая Firstmate в работу, остаётся в «В работе», пока нет подтверждённого ожидания или завершения, даже если текущее состояние исполнителя неизвестно.
Выполняемые проверки тоже относятся к работе; остановленная проверка, ожидающая решения, относится к «Ждёт».
Неизвестное состояние исполнителя само по себе не переносит задачу из очереди в работу.

В «Новой задаче» основные поля - описание, вид (`ship` или `scout`) и проект-папка.
Название получается из первого предложения описания; для одной ссылки используется адрес без параметров, агент может уточнить название по контексту.
Дело, дополнительная папка материалов только для чтения (для исследования), зависимость, дата «Отложить до» и «Личное» находятся в «Дополнительных сведениях».
Черновики дела, задачи и нового агента сохраняются в браузере во время ввода, после закрытия диалога и при ошибках отправки; успешное создание очищает соответствующий черновик.
Черновики разных домов Firstmate и агентов разных дел хранятся отдельно.
Выбранное дело записывается первой строкой описания: `Дело: <id>`.
URL из названия переносятся в начало описания строками `Источник: …`, без дублей.
Задача не запускается при создании.

Карточка задачи показывает название, «Зачем» из брифа, ссылки строки Firstmate (PR, рапорты, документы) и бриф: зачем, критерий готовности, контекст и ограничения. «Править» меняет название, описание и отметку «Личное»; прежнее описание уходит в архив заметок Firstmate. Бриф закрытой задачи заморожен.

Кнопки действий доступны в карточке, строках обзора, фокусе и списке задач дела и зависят от состояния строки:

- в очереди: «Взять в работу», «Пауза», «Закрыть», «Отказ»;
- на паузе: «Снять паузу», «Закрыть», «Отказ»;
- вопрос капитану или задача, ожидающая решения: «Ответить» или «Разрешить работу», «Позже», «Закрыть как неактуальную»;
- в работе: «Запросить остановку» и «Запросить закрытие», а если задача ждёт ответа, ещё «Ответить»: ответ снимает ожидание, и задача остаётся в работе;
- закрытая: «Вернуть».

«Взять в работу» и закрытие задачи в работе отправляют заметку firstmate: запуском и остановкой агентов управляет он. Карточка показывает такие запросы и их состояние; повторный щелчок по неподтверждённому запросу повторяет тот же запрос. Если Firstmate сейчас не принимает заметки, панель сообщает об этом.

«Закрыть как неактуальную» сначала просит подтверждение, затем сохраняет этот выбор в истории решения Firstmate и закрывает задачу.
Открытие страницы и отмена подтверждения ничего не меняют.
Строки показывают текущее состояние задачи; кнопки выполняют действие без перехода в карточку.
Пока запрос выполняется, все кнопки этой задачи в обзоре и фокусе недоступны; после ошибки можно повторить действие.

CLI доступен через `npm run delo --` или `bin/delo`:

```text
bin/delo list
bin/delo show идентификатор
bin/delo state идентификатор active|paused|done|dropped
bin/delo doctor
bin/delo publish-artifact файл-или-https-адрес --title название --action 'что требуется' [--task задача] [--root папка] [--request-id ключ]
```

Новую задачу из терминала заводит `fm-tasks-axi.sh add`.

## Дела

Дело - строка бэклога вида `program`: она стоит в работе без исполнителя, и Firstmate никогда не передаёт её агенту.
«Новое дело» начинает с описания, вида дела и проекта-папки; описание может состоять из одной ссылки и сохраняется в контексте брифа.
Зачем, критерий готовности, дополнительный контекст, ограничения и источники необязательны и находятся в «Дополнительных сведениях».
Проект - любая существующая папка: в одном поле можно ввести абсолютный путь или `~/…` либо выбрать недавно использованную папку; реестр Firstmate дополняет подсказки.
Выбор не регистрирует проект и не меняет файлы этой папки; проект сохраняется в деле и подставляется в «Новый агент».
Вид «Дежурство» по умолчанию читает папку проекта; другую папку материалов можно указать в дополнительных сведениях.
Дежурство сохраняет папку материалов только для чтения и использует [существующий duty-процесс](../docs/duty.md); сохранение дела не запускает агента.
Раздел «Дела» на главном экране перечисляет открытые дела со счётчиками задач: в работе, ждёт, дальше, сделано.
Страница дела показывает бриф, задачи дела из бэклога по состояниям, «Закрыты раньше» из архива Firstmate и «Ссылки»: источники, ссылки дела и всех его задач без повторов.
Бриф можно править, пока дело открыто.
«Новый агент» в открытом деле заводит задачу дела и сразу отправляет firstmate заметку «возьми в работу».
Форма задаёт направление (оно становится описанием, а его первое предложение - названием), режим работы, проект и исполнителя.
«Исследование» (`scout`) готовит отчёт и может читать отдельную папку материалов; «Изменение файлов» (`ship`) правит выбранный проект в изолированном рабочем дереве.
Папка материалов не становится местом для правок.
В обычном деле доступна отметка «Работаю в окне сам».
Дежурство запускает только исследование через claude с папкой только для чтения и источниками дела; оно не публикует ответы и не создаёт задачи Jira.
Описание задачи начинается строками `Дело: <id>`, `Исполнитель: <имя>` (если исполнитель выбран), `Интерактивно` (если отмечено) и `Папка: <путь>`.
Инструкции такой задачи, которые готовит `bin/fm-brief.sh`, включают бриф дела в момент подготовки; правка брифа доходит только до задач, инструкции которых ещё не готовы.
Страница задачи показывает выбранного исполнителя и того, кто на самом деле её выполняет.
«Открыть терминал» в карточке задачи и рядом с исполнителем в деле выбирает его существующую вкладку Herdr; затем переключитесь в окно Herdr.
Ожидание квоты и пауза не мешают переходу, пока терминал сохранился.
Закрытый терминал, изменившаяся привязка, вкладка с несколькими панелями и другие терминальные среды показываются как недоступные для перехода.
«Закрыть дело» сразу закрывает дело без незакрытых задач.
Если незакрытые задачи есть, сначала появляется предупреждение с их списком; только после подтверждения firstmate получает по заметке «закрой задачу» на каждую, и дело закрывается.
«Вернуть» открывает закрытое дело снова, пока оно в бэклоге.
«Закрытые дела» показывают дела из архива только для чтения; «Продолжить» заводит новое открытое дело с тем же названием, видом, проектом, папкой материалов, брифом и источниками.

## Ревью

В «Новом деле» доступны «Ревью системной аналитики» и «Код-ревью».
Для СА обязательны HTTP(S) ссылка на документ и существующая папка контекстного репозитория; можно выбрать папку из подсказок или ввести абсолютный путь либо `~/…`.
Ссылку можно передать в описании; отдельное поле в дополнительных сведениях позволяет явно выбрать документ или задачу для ревью.
Для код-ревью нужна одна ссылка на задачу Jira или конкретный PR, контекстный проект можно указать дополнительно.
Создание дела добавляет дочернюю задачу; «Взять в работу» передаёт её Firstmate через обычный запрос запуска.
Агент собирает связанные эпики и задачи СА, дополняет локальное описание ссылками и исполняет ревью.
SA runner запускает существующий npm script, а код-ревью использует code-review-workflow.
Карточка и отчёт показывают наблюдаемые переходы, времена и итог; неполные этапы и неизвестный формат отмечаются явно.
Ошибка или отмена остаются ошибкой, даже если процесс сообщил код выхода 0.
HTTP сервер не запускает ревью, а запросы создания и запуска защищены от повторов.

## Материалы на просмотр

Работник сдаёт предназначенный человеку файл, страницу или ссылку командой `publish-artifact`; инструкции, которые готовит `bin/fm-brief.sh`, требуют этого до завершения задачи.
Задача по умолчанию берётся из `FM_TASK_ID`; дело, проект и исполнитель - из записей Firstmate.
Команда копирует материал в `data/<задача>/artifacts/<id>/` дома Firstmate, поэтому он остаётся доступен после удаления исходника, рабочего дерева и остановки работника.
HTML копируется вместе со всеми файлами своей папки или папки `--root`: до 2000 файлов и 50 МиБ, без символьных ссылок, `.git` и `node_modules`.
HTTP(S) адрес записывается как ссылка: страница остаётся живой, Дело не сохраняет её копию.
Повтор с тем же ключом возвращает прежнюю запись, а другой материал под тем же ключом отвергается; без `--request-id` ключом служит отпечаток материала, поэтому изменённый материал становится новой публикацией.
Если описание задачи содержит строку `Продолжение материала: <id>`, новая публикация показывает ссылку на прежний материал.

«На просмотр» в шапке ведёт к общей очереди всех работников и показывает число необработанных материалов; о новых материалах панель сообщает без всплывающих окон.
Строка очереди показывает название, дело или проект, что требуется, исполнителя, время поступления и отметки «Есть черновик» и «Закреплено».
Закреплённые материалы стоят первыми, остальные - от старых к новым; есть поиск по названию, фильтр по делу или проекту и «Только начатые».

Материал открывается на столе во всю ширину окна.
HTML показывается в изолированном фрейме без доступа к панели и её API; изображения, аудио, видео, PDF и текст показываются на месте, ссылка открывается в новой вкладке, остальные файлы скачиваются.
К обычному материалу пишется комментарий: кнопка называется «Ознакомился», пока поле пустое, и «Передать комментарий», когда в нём есть текст.
Черновик сохраняется в доме Firstmate во время ввода и восстанавливается после перезагрузки панели или перезапуска сервиса.
«Убрать как неактуальное» просит причину и закрывает материал без одобрения содержания.

Интерактивный HTML отвечает своей кнопкой отправки.
Для него Дело даёт `window.lavish.queuePrompt` и `window.lavish.sendQueuedPrompts` и сохраняет поля ввода как черновик; ответ на вопрос `data-lavish-question` заменяет прежний ответ на тот же вопрос.
Аннотации, доска, загрузка файлов и другие возможности Lavish SDK не поддерживаются.
Пути от корня сайта (`/файл`) внутри материала не работают; собственная политика CSP материала может запретить этот адаптер.

Ответ записывается один раз и целиком; после записи стол возвращает к очереди, а материал уходит в «Архив».
Ответ больше 1 МиБ не отправляется: панель показывает ошибку, введённое остаётся на месте.
Firstmate получает заметку через `fm-inbox.sh` со ссылкой на полный ответ и его SHA-256; если заметка не сохранилась, сервис повторяет её при запуске и каждую минуту, без дублей.
Архив показывает ответ и состояние передачи; «Дополнить ответ» отправляет отдельное сообщение, не меняя прежний ответ.

## Пользовательский сервис systemd

Остановите прежний `npm start` через `Ctrl+C`, чтобы освободить порт 4317. Затем в обычном терминале, без `sudo`, выполните:

```text
npm run service:init
```

Команда создаёт `~/.config/systemd/user/delo.service` (или каталог из `XDG_CONFIG_HOME`), обновляет конфигурацию systemd, включает автозапуск при входе и запускает приложение. Повторная инициализация обновляет настройки и перезапускает сервис. Используются абсолютный путь к текущему Node.js, папка этого проекта и привычный PATH. Сервис запускается как `cli.ts serve` без `--home`; в файл всегда записывается `Environment=DELO_FIRSTMATE_HOME=…`: значение переменной, если она задана при инициализации, иначе тот же дом по умолчанию, что у сервера. После смены установки Node.js, переноса проекта или дома Firstmate повторите инициализацию.

Уже установленный сервис со строкой `--home /путь/.data` продолжает запускаться: флаг принимается и игнорируется, каталог не читается и не меняется.

После обновления кода:

```text
npm run service:restart
```

Перезапуск выполняет только `systemctl --user restart delo.service`. Переменные графического сеанса для фокусировки окна передаёт `service:init`; она же показывает состояние сервиса после запуска. После смены графического сеанса актуальные переменные должна передавать в systemd сама графическая сессия. Отдельный `npm start` одновременно с сервисом не запускайте.

Состояние, журнал и отключение автозапуска:

```text
systemctl --user status delo.service
journalctl --user -u delo.service -f
systemctl --user disable --now delo.service
```

Для разрешения только перезапуска из Codex оставьте глобальную политику без изменений. Создайте в этом проекте пустой `.codex/config.toml`, если его ещё нет, и файл `.codex/rules/delo-restart.rules`:

```python
prefix_rule(
    pattern = ["npm", "run", "service:restart"],
    decision = "allow",
)
```

После добавления правила перезапустите Codex с `codex resume --last`. Правило проекта разрешает указанную команду вне песочницы без подтверждения; инициализация в него не входит. Сопоставление можно проверить: `codex execpolicy check --rules .codex/rules/delo-restart.rules -- npm run service:restart`. Подробности — в [документации Codex о правилах](https://learn.chatgpt.com/docs/agent-configuration/rules). Правило нужно установить самостоятельно; скрипты сервиса его не добавляют.

## Проверка

```text
npm test
npm run check
npm run build
```

Тесты используют временные дома Firstmate, а команды агентов, Herdr и `systemctl` в них заменены заглушками. Каждый временный дом Firstmate получает ссылку `bin` на код Firstmate: по умолчанию `~/Projects/firstmate/bin`, другой путь задаёт `DELO_TEST_FIRSTMATE_BIN`. Тест сервиса проверяет только текст файла сервиса и не вызывает `systemctl`.
